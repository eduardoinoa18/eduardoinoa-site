# tools/data

## recent-sales.json — read this before adding anything

`recent-sales.json` feeds the "Recent sales" section on `/listings` and `/es/propiedades`
(generated by `tools/pages/journal.mjs`). While the file is an empty array (`[]`), the section
is not rendered at all. JSON has no comments, so the rules live here.

Rules (NAR Code of Ethics Art. 12; MA 254 CMR 3.00(9); MA Ch. 93A; NH Rea 404.05):

1. Only real transactions Eduardo was part of. Never invent, round up or "illustrate" a sale.
2. `price` and `closeDate` come from the MLS record only (MLS PIN or NEREN), never from memory,
   a CMA or a client conversation. Put the MLS name in `mlsSource` and the number in `mlsNumber`.
   An entry without `price`, `closeDate` and `mlsSource` is skipped by the generator.
3. The street address is shown only when the client has said yes to it. Record that with
   `"addressOk": true`; otherwise leave `address` empty and only the town is shown.
4. `side` says who Eduardo represented: "seller", "buyer" or "both". If another brokerage listed
   the home, the card says "Represented the buyer", never implies Eduardo listed it.
5. `photo` is optional: a slug from `img/photos/manifest.json` or a path under `/img/` that we
   have the rights to. No MLS photos unless the license allows reuse on this site.
6. Fair Housing: describe the home and the town, never who lives there or who bought it.

Entry shape:

```json
{
  "town": "Methuen", "state": "MA",
  "address": "", "addressOk": false,
  "side": "seller",
  "propertyType": "Single-family",
  "price": 0, "closeDate": "YYYY-MM-DD",
  "mlsSource": "MLS PIN", "mlsNumber": "",
  "photo": ""
}
```

After editing, run `cd tools && ONLY=journal.mjs node generate.mjs` (then a full `npm run gen`).

## posts.json

Journal metadata (titles, summaries, covers, related reading, town chips) for `/journal`,
`/es/blog` and the Spanish posts. The English posts in `/posts/*.html` are hand-written pages;
when you edit a title or summary there, update it here too.
